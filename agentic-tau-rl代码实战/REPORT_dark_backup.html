🎯 底座：tau2-bench

Sierra 的 dual-control 客服 benchmark（retail / airline / telecom）。用户是活的 LLM，会 STOP / TRANSFER；工具有副作用；reward 靠数据库终态断言。纯 Python 无 docker，离线可 mock。

03 三个最有价值的实现点

① 数据是真的，验证是硬的

5 条 golden fixture 取自冷启动同源数据，带真实 reward_info。照 tau2 官方 evaluator 复刻乘法门控语义 reward = ∏ component[c]，逐条对拍真实 gold 值全部通过——覆盖 [DB,COMMUNICATE] 与 [ENV_ASSERTION] 两种 basis。这比"跑通就行"强得多。

② 信用分配三种打法并存，且真能看出差异

outcome / R2G / InfoPO 在同一条 rollout 上可切换。最关键：InfoPO 的反事实 info-gain 在 tiny model 上真算 KL（factual vs masked 下一步分布），验证了 survey 核心命题——零方差组（GRPO 梯度≈0 学不动）靠 info-gain 产生非平凡梯度被救活。

③ 修了一个真实的 credit assignment bug

demo 里 success_logprob 一开始在下降。根因是 R2G 的 turn-level 归一化被错误地写在单条轨迹内（traj_adv*(1+nv)），把成功轨迹早期轮翻成负 advantage。正确做法是在整个 group 层面统一归一化——这正是 agentic RL 最易踩的坑。修完后 logprob 从 -6.3 稳升到 -5.1。

06 两个诚实的边界

tau2 需 Python ≥ 3.12

当前离线环境是 3.9，装不上真实 tau2，故用 mock env + 真实 gold reward_info 交叉验证（最强证明）。真机适配器与 skipif 集成测试已就位，环境满足时自动激活。

BAO 超参论文未公开

λ_ans / λ_think / w 的具体数值 survey 也指出论文未披露。代码用占位默认值，公式与思想严格对齐，真机需自行调参。
